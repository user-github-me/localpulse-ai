# LocalPulse AI v1.1.0

This source update adds private research, study, writing and follow-up tools, with an easier,
optional email read-activity workflow. It is free and MIT-licensed. Browser-store publication
is a separate step after review of [PR #11](https://github.com/user-github-me/localpulse-ai/pull/11).

## Update details

- Enable email tracking in onboarding. Gmail and Outlook drafts receive separate random images,
  per-draft toggles and local estimated-read badges. Optional generic notifications, private image
  names, an encrypted service test and password-encrypted backups are available in the dashboard.
- Save chosen research sources as local collections, search their text, rename, delete and
  export/import them. Reopened sources require fresh consent before cloud AI use.
- Open checked quotations in their actual source context, with extracted PDF page numbers.
- Recognize images and scanned PDFs locally with seven OCR languages; transcribe chosen audio
  locally with Whisper tiny English. Explicit downloads fetch model data; executable runtimes
  ship in the extension. Review, correct or export results and add them to the workspace.
- Preview duplicate tabs, confirm closing, group by domain in Chrome and save/restore named
  sessions locally.
- Search Wikipedia with a query you type, or configure a public SearXNG JSON endpoint. Fetch
  only sources you select. Private page context is never automatically attached to search.
- Use 24 searchable quick actions, a multi-document workspace, improved local conversation
  history, interactive flashcards, installed-voice read-aloud and a local follow-up board.
- Shortcut guidance follows the operating system and actual configured binding, including
  guidance when the binding is unassigned.
- Fixed production startup without optional alarm permission so onboarding and toolbar actions
  work on a fresh install. Fixed media-model readiness during dialog effect cleanup.

## Tracking privacy

Tracking never sends email subjects, bodies, recipients or private names. Public cryptographic
keys create image capabilities. A separate public open-source service encrypts image-request
timestamps for the extension and queues ciphertext without expiry. The extension saves decrypted
results locally before signing deletion of those exact queued events. Private keys stay local or
in a password-encrypted backup. No link tracking, recipient identification or message content is
collected by tracking.

Hosting providers can observe network metadata and retain platform logs. Image requests can be
preloads, scanners or proxy fetches; counts cannot prove human reading, delivery or unique people.
Gmail/Outlook can cache later opens. Free hosting and bounded queues can miss requests. The public
service code and complete policies are in [tools/email-tracker](../../tools/email-tracker/README.md)
and [PRIVACY.md](../../PRIVACY.md).

## Local packages

Run `corepack pnpm zip` and `corepack pnpm zip:firefox` for store ZIPs and reviewer source ZIPs.
For this project's existing verified-upload setup, `corepack pnpm crx` reuses `local/key.pem`
and verifies the signature, public key, version and every packaged file against the Chrome ZIP.
Keys are excluded from Git and the source ZIP. Contributors use their own signing setup; never
commit a private signing key.

Load `local/build/chrome-mv3` through Chrome's **Load unpacked** to test locally. The e2e build
has extra permissions and must not be submitted. Upload the production ZIP through the store's
standard package flow. If Verified CRX Uploads is already enabled for the item, use the signed
CRX. The store re-signs its distribution. This preparation does not publish an update.

Prepared local assets are in `local/releases/v1.1.0`: packages, checksums, release notes, listing,
privacy answers, reviewer instructions and screenshots. [Store preparation](../store/v1.1.0.md)
describes the disclosures and verification requirements.

## Compatibility and verification limits

Automated browser checks exercise deterministic provider fixtures and synthetic Gmail/Outlook
pages. They do not establish compatibility with every authenticated mail layout, every cloud
provider account or every operating-system browser. OCR and Whisper real-model tests are opt-in
because they download public model data. In-browser WebLLM needs supported WebGPU hardware;
Firefox uses local apps or cloud providers instead. Audio supports English and formats the
browser can decode; accuracy varies. The generated test report records actual completed checks.

Feature issues remain open until PR review and merge. Its `Closes` links then close them
automatically, preserving implementation and review history for contributors.
